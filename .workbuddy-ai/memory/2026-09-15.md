## node 模式:代理保活拆出独立内置周期（用户要求）

用户问「server 改了账号密码端口会自动重启代理么 / 代理掉线会自动重启么」，我读代码后答：

- **信息变了会自动重启** ✓（每轮 `Tick` 拉一次信息，`sameConn` 比 `Type/Port/Value1/Value2`）
- **运行中掉线不会重启** ✗ —— `Serve()` 返回只记日志，`Runner.proxy` 仍指向死掉的服务，
  下一轮因 `sameConn` 为真直接 return

用户随即指出关键：**「拉节点信息 + 起代理」的周期和 `scheduler` 不是一回事，这个要内置写死**
（`scheduler` 驱动的是重活"检测 + 上报"，代理保活是轻活，必须高频）。据此改成：

| | 之前 | 现在 |
|---|---|---|
| 拉节点信息 + 保代理 | 跟着 `Tick`（cron，可能 1 小时一次） | `Runner.Watch(ctx)` 常驻，**内置 `proxyInterval = 30s`** |
| `Tick` | 拉信息 + 起代理 + 检测 + 上报 | **只管检测 + 上报** |
| 服务退出信号 | 没有 | `startProxy` 返回 `done <-chan struct{}`，`Serve()` 返回时关闭 |

- `ensureProxy` 改用 `switch { case exited(r.done): 重起; case sameConn(...): return; default: 重启 }`
  —— 服务已退出时**跳过 Close**（句柄已失效，避免对已停服务再 Close）
- `main.go` 的 `runNode` 里加 `go r.Watch(ctx)`
- 新增测试 `TestEnsureProxyRestartsAfterExit`：关掉服务 → 等 `done` 关闭 → 信息没变也应换一个新服务 ✓
- node 包 7 个测试全过；全模块只有 `internal/detect` 那个**既有**问题

### static 包重构：`server/internal/static/*` → `server/internal/static/web/*`

`//go:embed` 的实测结论（本轮花了几次实验搞清楚的）：

- `//go:embed all:*` **会把 `static.go` 自己嵌进二进制** → `GET /static.go` 能读到 Go 源码
- 换成 `*`（不带 `all:`）**同样含 `.go`** —— `*` 只排除以 `.` 和 `_` 开头的文件，**不排除 `.go`**
- `//go:embed all:web` 只嵌一个子目录 → 不含 `.go`；目录里只有 `.gitkeep`（隐藏文件）时**也能编译**

最终写法：`//go:embed all:web` + `fs.Sub(embedded, "web")` 剥掉前缀，把 `web/` 当 FS 根，
后面的静态路由与 SPA 回退代码不用再改路径。前端未构建时 `fs.Stat(staticFS,"index.html")` 失败 →
返回一个带构建指引的 `placeholder` 提示页（原来是白页）。

连带改的 5 处引用点：

- `.gitignore` —— 忽略 `web/` 内容但保留 `.gitkeep`：`/server/internal/static/web/*` + `!.../.gitkeep`
  （**embed 要求目标非空**，所以 `.gitkeep` 不能删）
- `.dockerignore` —— 排除 `server/internal/static/web`（镜像内会放新构建的）
- `scripts/build.sh` —— `EMBED_DIST` 指向 `web`；清理用 `find -mindepth 1 ! -name '.gitkeep'`
  而不是删 `*.go`；`SKIP_WEB=1` 的语义改成"**只跳过构建，同步照做**"，且 `web/dist` 缺失时**明确报错退出**
- `.github/workflows/server.yml` —— 同步步骤同步改目录
- `server/Dockerfile` —— `COPY --from=web /src/web/dist/ ./internal/static/web/`

## 首次 CI 跑出来的真 bug：release job 的 `gh` 认不出仓库

首轮 tag 触发的两个 workflow：**build（两个架构）全 success，但 release job 都 failure**。

日志里的关键两行：

```
failed to run git: fatal: not a git repository (or any of the parent directories): .git
##[error]Process completed with exit code 1
```

**根因**：`release` job 的 steps 只有 `actions/download-artifact` + `gh release ...`，
**没有 `actions/checkout`** → 工作目录里没有 `.git` → `gh` 既没有 git remote 也没有别的线索
去判断"操作哪个仓库"，于是 `gh release view` / `create` 全部直接死在"跑 git"这一步。
`GH_TOKEN` 只解决**认证**，解决不了**定位仓库**。

**修法**：在 step 的 `env` 里加 `GH_REPO: ${{ github.repository }}`
（比加一个 `actions/checkout` 轻，checkout 只为让 gh 找到 remote 而拉整仓不值）。
两个 workflow 各一处 —— `agent.yml` 与 `server.yml` 的「附到 Release」都改了。

**注意**：**改 workflow 后不能靠"Re-run failed jobs"生效** —— tag 触发的 run 用的是
**tag 那个 commit 上的 workflow 文件**，所以必须**把 tag 移到新 commit 上重推**才会用新文件。

### 观察到的其它事实

- docker job（`needs: build`）确实排在 build 之后，且两个架构的 build 全绿才启动 ✓
- `actions/download-artifact@v4` 报 `Node.js 20 is deprecated`（官方 action 的提示，非本项目问题）
- 这一轮**真正验证了 `needs: build` 的价值**：如果 build 挂了，镜像不会被推
