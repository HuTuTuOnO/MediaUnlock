## node 模式:代理保活拆出独立内置周期（用户要求）

用户问「server 改了账号密码端口会自动重启代理么 / 代理掉线会自动重启么」，我读代码后答：

- **信息变了会自动重启** ✓（每轮 `Tick` 拉一次信息，`sameConn` 比 `Type/Port/Value1/Value2`）
- **运行中掉线不会重启** ✗ —— `Serve()` 返回只记日志，`Runner.proxy` 仍指向死掉的服务，
  下一轮因 `sameConn` 为真直接 return

用户随即指出关键：**「拉节点信息 + 起代理」的周期和 `scheduler` 不是一回事，这个要内置写死**
（`scheduler` 驱动的是重活"检测 + 上报"，代理保活是轻活，必须高频）。据此改成：

| | 之前 | 现在 |
|---|---|---|
| 拉节点信息 + 保代理 | 跟着 `Tick`（cron，可能 1 小时一次） | `Runner.Watch(ctx)` 常驻，**内置 `proxyInterval = 30s`** |
| `Tick` | 拉信息 + 起代理 + 检测 + 上报 | **只管检测 + 上报** |
| 服务退出信号 | 没有 | `startProxy` 返回 `done <-chan struct{}`，`Serve()` 返回时关闭 |

- `ensureProxy` 改用 `switch { case exited(r.done): 重起; case sameConn(...): return; default: 重启 }`
  —— 服务已退出时**跳过 Close**（句柄已失效，避免对已停服务再 Close）
- `main.go` 的 `runNode` 里加 `go r.Watch(ctx)`
- 新增测试 `TestEnsureProxyRestartsAfterExit`：关掉服务 → 等 `done` 关闭 → 信息没变也应换一个新服务 ✓
- node 包 7 个测试全过；全模块只有 `internal/detect` 那个**既有**问题
